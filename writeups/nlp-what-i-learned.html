NLP: What I Actually Learned

Notes from my Natural Language Processing module — what clicked, what didn't at first, and why NLP turns up more often in security than most people expect.

What NLP Actually Is

Natural Language Processing is the field of getting computers to understand, interpret, and generate human language. That sounds straightforward until you realise how much implicit context humans pack into ordinary sentences — sarcasm, ambiguity, cultural references, typos that still make sense.

The module covered the core pipeline from raw text to something a model can work with. That pipeline is where most of the interesting (and painful) work happens.

Tokenisation — Not as Simple as Splitting on Spaces

Tokenisation is splitting text into units (tokens) that the model can process. The naive approach — split on whitespace — falls apart immediately in practice. 

# Naive split — breaks on punctuation, contractions, etc.
text   = "I can't believe it's not butter."
tokens = text.split()
# ["I", "can't", "believe", "it's", "not", "butter."]
# "butter." still has the period attached — that's a problem

# Better: use a proper tokeniser
import nltk
tokens = nltk.word_tokenize(text)
# ["I", "ca", "n't", "believe", "it", "'s", "not", "butter", "."]

Notice how can't becomes ca + n't. That's intentional — it separates the root word from the negation marker, which matters for sentiment analysis. The tokeniser is making linguistic decisions, not just splitting strings.

Subword tokenisation

Modern models (like BERT and GPT) use subword tokenisation — words get broken into smaller pieces based on frequency in the training data. The word "unhappiness" might become ["un", "##happ", "##iness"]. This handles rare words and typos better than whole-word approaches because it can still encode meaning from the subcomponents it has seen before.

Word Embeddings — Turning Words Into Numbers

Models can't process strings — everything has to become numbers. Embeddings are the standard solution: each word gets mapped to a dense vector (a list of floats) that represents its meaning in a high-dimensional space.

king → [0.21, -0.45, 0.88, 0.13, ...]

queen → [0.19, -0.42, 0.71, 0.35, ...]

cat → [-0.55, 0.67, -0.12, 0.90, ...]

What makes embeddings powerful is that words with similar meanings end up close to each other in the vector space. The classic demonstration is the word arithmetic: 

# vector("king") - vector("man") + vector("woman") ≈ vector("queen")
# The model has encoded semantic relationships as geometric relationships

This is the same concept as facial recognition encodings. Both convert something complex (a face, a word) into a vector where similarity in meaning corresponds to proximity in space. The maths is the same — Euclidean or cosine distance.

What the Module Covered in Practice

Sentiment analysis

Classifying text as positive, negative, or neutral. The tricky cases are negation ("not bad" is positive) and context-dependent words ("sick" is negative in most contexts, positive in slang). This was one of the first hands-on tasks — building a basic classifier using labelled review data.

Named entity recognition (NER)

Identifying proper nouns in text — people, places, organisations, dates. Useful for information extraction at scale. A model trained on news articles can pull out every person and location mentioned across thousands of documents in seconds.

Text classification

Given a piece of text, assign it a category — spam vs not spam, malicious vs benign, topic classification. This is where the security relevance becomes direct.

Why NLP Keeps Showing Up in Security

Phishing detection

Email filtering at scale uses NLP to flag phishing attempts. A model trained on known phishing emails learns patterns — urgency language, impersonation phrases, suspicious sender patterns combined with body text analysis. Simple regex rules get evaded easily; a classifier trained on embeddings is much harder to fool.

Log analysis and threat detection

Security logs are just text. NLP techniques — specifically anomaly detection on sequences — can flag unusual patterns in log streams. If a sequence of log entries looks statistically unlike anything seen before, that's worth investigating.

Malware analysis

Malware often includes strings — error messages, function names, hardcoded URLs. Classifiers trained on string data can distinguish benign software from malicious samples with reasonable accuracy, even without running the code.

LLMs as an attack surface

This is the newest angle. Large language models themselves are now targets. Prompt injection — hiding instructions in user-supplied input that cause the model to ignore its system instructions — is an active area of security research. Understanding how tokenisation and context windows work is directly relevant to understanding these attacks.

What I Found Hard

The gap between "I understand the concept" and "I can build it" was steeper than expected. Getting a sentiment classifier working was straightforward. Getting it to handle negation properly, or sarcasm, or domain-specific language, was much harder. The model doesn't understand language — it's learned statistical patterns from training data, and when you stray from that distribution, it breaks.

That framing — models as pattern matchers, not comprehenders — changed how I think about using them in security contexts. They're useful tools but they fail in predictable ways when the input doesn't resemble training data, and attackers will find those edges.
